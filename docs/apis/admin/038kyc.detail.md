# GET /api/admin/kyc/:cz_kyc_verification_id

One verification attempt, the user behind it, and every other attempt that user has made. The detail page a KYC tab row opens.

## Overview

| Item | Value |
|---|---|
| **Method** | `GET` |
| **Path** | `/api/admin/kyc/:cz_kyc_verification_id` |
| **Auth** | Bearer **Rewardtym** admin access token required. |
| **Role** | admin |
| **Rate limit** | default (120/min) |

## Request

### Headers

| Header | Required | Value |
|---|---|---|
| `Authorization` | yes | `Bearer <admin_access_token>` |

### Path / query params

| Name | Type | Required | Description |
|---|---|---|---|
| `cz_kyc_verification_id` | string (uuid) | yes | From a `GET /api/admin/kyc` row. |

### Body

None.

## Response

### Success — `200`

| Field | Type | Description |
|---|---|---|
| `attempt.cz_kyc_verification_id` | string (uuid) | Primary key of this attempt. |
| `attempt.user_id` | string (uuid) | Who submitted it. |
| `attempt.selfie_url` | string | The uploaded selfie, stored in R2. |
| `attempt.rekognition_score` | number \| null | Face-match confidence, 0 to 100. |
| `attempt.rekognition_response` | object \| null | The raw face-detection payload: face count, confidence, eyes open, sharpness, occlusion. Kept for disputes. |
| `attempt.status` | string | Outcome of this attempt. |
| `attempt.rejection_code` | string \| null | Machine-readable reason. |
| `attempt.rejection_reason` | string \| null | The wording the user was shown. |
| `attempt.reviewed_by` | string \| null | Rewardtym admin id, or `null` when the system decided automatically. |
| `attempt.reviewed_at` | string (date-time) \| null | When the decision landed. |
| `attempt.created_at` | string (date-time) | When the selfie was submitted. |
| `user.cz_user_id` | string (uuid) | The account. |
| `user.email` | string | Their email. |
| `user.name` | string \| null | Their display name. |
| `user.avatar_url` | string \| null | Their profile photo. |
| `user.country` | string \| null | ISO country code. |
| `user.status` | string | Account state. |
| `user.kyc_status` | string | Their **current** KYC standing, which may be newer than this attempt. |
| `user.joined_at` | string (date-time) | When the account was created. |
| `attempts.data[]` | array | Every attempt this user has made, newest first, including this one. Same shape as `attempt`. |
| `attempts.total` | integer | How many attempts that is. |

## Enum values

| Field | Allowed values | Notes |
|---|---|---|
| `attempt.status` / `attempts.data[].status` | `pending`, `verified`, `rejected`, `manual_review` | |
| `attempt.rejection_code` | `CZDKYC004`, `CZDKYC005` | No face found, and more than one face. `null` otherwise. |
| `user.kyc_status` | `none`, `pending`, `verified`, `rejected`, `manual_review` | |
| `user.status` | `active`, `suspended`, `banned`, `deleted` | |

## Example

```bash
curl "$BASE/admin/kyc/1c7a9f22-4d3b-4e08-9b51-6f0e2a7d3c14" \
  -H 'Authorization: Bearer $ADMIN_TOKEN'
```

## Notes

- `attempts` is the whole history for this user, so repeat failures and the pattern behind them are visible on one screen. That history is deliberately never exposed to the user.
- `attempt.rekognition_response` is the raw detector output, kept so a disputed rejection can be re-read rather than re-argued.
- `reviewed_by` is `null` on an automatic decision. A value means a person made the call.
- There is no endpoint to approve or reject from the panel yet. This is read-only; `manual_review` rows are worked outside the app for now.
- Compare `attempt.status` with `user.kyc_status`: they differ whenever the user submitted again after this attempt.
- Admin access uses the **Rewardtym admin token**. There is no Coinzu admin account or Coinzu admin sign-in. The token must carry `type: "admin"` and a `product_access` claim of `both` or `coinzu`. A token issued before that claim existed falls back to the older rule: its `role` claim must be listed in the `ADMIN_ROLES` env var. It is verified with the shared `JWT_AUTH_TOKEN` secret and never looked up in the database.
