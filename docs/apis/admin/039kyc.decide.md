# POST /api/admin/kyc/:cz_kyc_verification_id/decision

Approves or rejects an identity check the face match could not settle on its own, and overrides one it rejected automatically. **Super admin only.** Writes the attempt, moves the account's standing with it, and tells the user in-app.

## Overview

| Item | Value |
|---|---|
| **Method** | `POST` |
| **Path** | `/api/admin/kyc/:cz_kyc_verification_id/decision` |
| **Auth** | Bearer **Rewardtym** admin access token required. |
| **Role** | admin, **and** the token's `role` claim must be `super_admin` |
| **Rate limit** | default (120/min) |

## Request

### Headers

| Header | Required | Value |
|---|---|---|
| `Content-Type` | yes | `application/json` |
| `Authorization` | yes | `Bearer <admin_access_token>` |

### Path / query params

| Name | Type | Required | Description |
|---|---|---|---|
| `cz_kyc_verification_id` | string (uuid) | yes | The attempt to settle. |

### Body

| Field | Type | Required | Rules | Description |
|---|---|---|---|---|
| `decision` | string | yes | `approve` or `reject`. | The verdict. |
| `reason` | string | no | Max 300 characters. | Shown to the user on a rejection. Ignored on an approval. A default is used when omitted. |

```json
{
  "decision": "reject",
  "reason": "The selfie does not match the document on file."
}
```

## Response

### Success — `201`

Identical to `GET /api/admin/kyc/:cz_kyc_verification_id`, so the screen can render the settled attempt straight from the response.

| Field | Type | Description |
|---|---|---|
| `attempt` | object | The attempt, now `verified` or `rejected`, with `reviewed_by` and `reviewed_at` filled in. |
| `user` | object \| null | The account, with `kyc_status` already moved. |
| `attempts.data[]` | array | Every attempt this user has made, newest first. |
| `attempts.total` | integer | How many that is. |

|---|---|---|---|---|

| 401 | `CZDAUTH005` | Please sign in to continue. | Authorization header is missing. | `SignInRequiredIcon` |
| 401 | `CZDAUTH003` | Your session has expired. Please sign in again. | Access token expired. | `SessionExpiredIcon` |
| 401 | `CZDAUTH004` | Your session is no longer valid. Please sign in again. | Access token could not be verified. | `SessionInvalidIcon` |
| 403 | `CZDAUTH007` | You do not have permission to do that. | The token's `role` claim is not `super_admin`, or its `product_access` claim is neither `both` nor `coinzu`. | `PermissionDeniedIcon` |

## Enum values

| Field | Allowed values | Notes |
|---|---|---|
| `decision` | `approve`, `reject` | |
| `attempt.status` | `pending`, `verified`, `rejected`, `manual_review` | `pending`, `manual_review` and `rejected` are all decidable. Only `verified` is final — deciding one is a 409. |
| `user.kyc_status` | `none`, `pending`, `verified`, `rejected`, `manual_review` | Set to `verified` on approve and `rejected` on reject. |

## Example

```bash
# Approve
curl -X POST "$BASE/admin/kyc/ca290ec5-4371-4e39-b02e-4432b9aae1fb/decision" \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer $ADMIN_TOKEN' \
  -d '{ "decision": "approve" }'

# Reject with the wording the user will read
curl -X POST "$BASE/admin/kyc/d5ececdf-9fcc-4c6f-9e7d-6c6d5861351b/decision" \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer $ADMIN_TOKEN' \
  -d '{ "decision": "reject", "reason": "The selfie does not match the document on file." }'
```

## Notes

- **Super admin only.** A `partner_admin` token can still open and read the whole KYC tab; only this route is closed to it. The check reads the token's `role` claim — there is no Coinzu-side role table.
- **A rejection can be overridden, a verification cannot.** `pending`, `manual_review` and `rejected` are all decidable, so an admin can approve a selfie the detector wrongly turned down. Once an attempt is `verified` it is final and any further call is a 409 — revoking a verification is not a KYC-tab action.
- The decision writes three things in one call: the attempt's `status`, the account's `kyc_status`, and an in-app notification for the user. The user is never shown `reviewed_by`.
- On approve, `rejection_reason` and `rejection_code` are cleared. On reject, `rejection_code` stays `null` — that field is only for the automatic detector's reasons (`CZDKYC004`, `CZDKYC005`), not a human's.
- `reviewed_by` is taken from the admin token's subject, never from the body.
- The app learns the outcome from `GET /api/users/me` (`kyc_status`) and its notification feed. It never sees the attempt history.
- All dates and times are UTC, ISO-8601 with a `Z` suffix.
