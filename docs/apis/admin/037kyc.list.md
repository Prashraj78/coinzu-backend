# GET /api/admin/kyc

Every identity-verification attempt with the user who made it, filterable, plus a count per outcome. The KYC tab.

## Overview

| Item | Value |
|---|---|
| **Method** | `GET` |
| **Path** | `/api/admin/kyc` |
| **Auth** | Bearer **Rewardtym** admin access token required. |
| **Role** | admin |
| **Rate limit** | default (120/min) |

## Request

### Headers

| Header | Required | Value |
|---|---|---|
| `Authorization` | yes | `Bearer <admin_access_token>` |

### Path / query params

| Name | Type | Required | Description |
|---|---|---|---|
| `page` | integer | no | 1-based page number. Default `1`. |
| `limit` | integer | no | Rows per page, max 100. Default `20`. |
| `search` | string | no | Case-insensitive match against the user's email or name. |
| `status` | string | no | One outcome. See [Enum values](#enum-values). |
| `date_from` | string (date) | no | Submitted on/after this UTC date (inclusive), `yyyy-MM-dd`. |
| `date_end` | string (date) | no | Submitted on/before this UTC date (inclusive), `yyyy-MM-dd`. |

### Body

None.

## Response

### Success — `200`

| Field | Type | Description |
|---|---|---|
| `data[].cz_kyc_verification_id` | string (uuid) | Primary key of the attempt. |
| `data[].selfie_url` | string | The uploaded selfie, stored in R2. |
| `data[].rekognition_score` | number \| null | Face-match confidence, 0 to 100. `null` if the check never ran. |
| `data[].status` | string | Outcome of this attempt. |
| `data[].rejection_code` | string \| null | Machine-readable reason. See [Enum values](#enum-values). |
| `data[].rejection_reason` | string \| null | The wording the user was shown. |
| `data[].reviewed_by` | string \| null | Rewardtym admin id, or `null` when the system decided automatically. |
| `data[].reviewed_at` | string (date-time) \| null | When the decision landed. |
| `data[].created_at` | string (date-time) | When the selfie was submitted. |
| `data[].user.cz_user_id` | string (uuid) | Who submitted it. Links to `GET /api/admin/users/:cz_user_id`. |
| `data[].user.email` | string | Their email. |
| `data[].user.name` | string \| null | Their display name. |
| `data[].user.avatar_url` | string \| null | Their profile photo. |
| `data[].user.country` | string \| null | ISO country code. |
| `data[].user.kyc_status` | string | The account's **current** state, which may be newer than this attempt. |
| `total` | integer | Attempts matching the filters, all pages. |
| `counts.pending` | integer | Attempts awaiting a result. |
| `counts.verified` | integer | Attempts that passed. |
| `counts.rejected` | integer | Attempts that failed outright. |
| `counts.manual_review` | integer | Attempts waiting on a person. |
| `counts.total` | integer | Every attempt ever, ignoring the filters. |

## Enum values

| Field | Allowed values | Notes |
|---|---|---|
| `status` / `data[].status` | `pending`, `verified`, `rejected`, `manual_review` | `manual_review` is a clear face that fell short of the confidence threshold, or was blurry, blinking or covered. |
| `data[].rejection_code` | `CZDKYC004`, `CZDKYC005` | `CZDKYC004` no face found, `CZDKYC005` more than one face. `null` when the attempt was not rejected. |
| `data[].user.kyc_status` | `none`, `pending`, `verified`, `rejected`, `manual_review` | `none` on an account that never submitted. |

## Example

```bash
curl "$BASE/admin/kyc?status=manual_review&date_from=2026-08-01&page=1&limit=20" \
  -H 'Authorization: Bearer $ADMIN_TOKEN'
```

## Notes

- **One row per attempt, not per user.** A user who tried three times appears three times. `data[].user.kyc_status` is their standing today, so an old rejected attempt can sit next to a `verified` account.
- Newest first. Every filter combines as `AND`; the dates filter on `created_at`, both inclusive, in UTC.
- `counts` is computed over the **whole** table, not the filtered page, so the header tiles stay stable while filtering.
- Users never see this. The app gets its decision from `POST /api/kyc/verify` and its standing status from `GET /api/users/me`.
- `rekognition_score` is the raw face-match confidence. The pass mark is the `kyc_confidence_threshold` setting, tunable in Configuration Settings.
- Admin access uses the **Rewardtym admin token**. There is no Coinzu admin account or Coinzu admin sign-in. The token must carry `type: "admin"` and a `product_access` claim of `both` or `coinzu`. A token issued before that claim existed falls back to the older rule: its `role` claim must be listed in the `ADMIN_ROLES` env var. It is verified with the shared `JWT_AUTH_TOKEN` secret and never looked up in the database.
