# POST /api/kyc/verify

**The only KYC call the app makes.** Upload the selfie and this one response tells you everything: the decision, the new account status, why it failed if it did, and whether the user may try again. There is no separate status or attempts endpoint.


Uploads a selfie for identity verification and decides on it in the same call using AWS Rekognition face detection.

## Overview

| Item | Value |
|---|---|
| **Method** | `POST` |
| **Path** | `/api/kyc/verify` |
| **Auth** | Bearer access token required. |
| **Role** | any signed-in user |
| **Rate limit** | Global default: 120 requests per minute per IP. |

## Request

### Headers

| Header | Required | Value |
|---|---|---|
| `Content-Type` | yes | `multipart/form-data` |
| `Authorization` | yes | `Bearer <access_token>` |

### Path / query params

None.

### Body

| Field | Type | Required | Rules | Description |
|---|---|---|---|---|
| `file` | file | yes | JPEG, PNG or WebP, at most 5 MB. | The selfie to verify. One face, eyes open, no sunglasses. |

Sent as `multipart/form-data`, not JSON. The field name is exactly `file`.

## Response

### Success — `201`

The same four-field shape is returned for every outcome. Read `status` to know what happened.

| Field | Type | Description |
|---|---|---|
| `cz_kyc_verification_id` | string (uuid) | Primary key of this attempt. |
| `kyc_status` | string | The account's KYC state after this submission. Same value as `status`, named to match `GET /api/users/me`. |
| `can_retry` | boolean | Whether the user may submit another selfie. `false` once verified or while a review is open. |
| `is_final` | boolean | `true` only when `status` is `verified`. Nothing more is needed from the user. |
| `submitted_at` | string (date-time) | When this attempt was recorded. |
| `status` | string | `verified`, `manual_review` or `rejected`. Never `pending` on this route. |
| `reason_code` | string \| null | Set only when the photo was rejected automatically: `CZDKYC004` or `CZDKYC005`. `null` otherwise. |
| `message` | string | A sentence that can be shown to the user as-is. |
| `selfie_url` | string | Public URL of the stored photo. |

The face confidence score and the raw Rekognition payload are **never** returned here. They are stored on the row and visible only to admins.

#### Outcome — `verified`

One clear face, confidence at or above the `kyc_confidence_threshold` setting, eyes open, no sunglasses, face not obscured, photo sharp enough.

```json
{
  "success": true,
  "data": {
    "cz_kyc_verification_id": "65681e52-8ce4-44f2-a5d5-f4b7465f21de",
    "status": "verified",
    "reason_code": null,
    "message": "Your identity is verified. Withdrawals are unlocked.",
    "selfie_url": "https://cdn.coinzu.app/kyc/0e2d46f5-a4ff-4b1c-b52a-5336a78d3726.jpg"
  }
}
```

#### Outcome — `manual_review`

Exactly one face, but the check was not confident enough to pass it on its own: below the threshold, or sunglasses, or eyes closed, or the face partly covered, or the photo too blurry. A person settles it, usually within a day. Nothing more is required from the user.

```json
{
  "success": true,
  "data": {
    "cz_kyc_verification_id": "46654bf1-37b9-4d1f-8c70-26969a95f55c",
    "status": "manual_review",
    "reason_code": null,
    "message": "Thanks — a team member is checking your photo. This usually takes a day.",
    "selfie_url": "https://cdn.coinzu.app/kyc/fd659aa6-1383-44d1-b58f-1ac4533c241c.jpg"
  }
}
```

#### Outcome — `rejected`

No face at all, or more than one face. The photo cannot be judged, so the user has to retake it. `message` already says what to fix.

```json
{
  "success": true,
  "data": {
    "cz_kyc_verification_id": "a0ec74fb-5054-4849-b694-ff101062032d",
    "status": "rejected",
    "reason_code": "CZDKYC004",
    "message": "We could not find a face in that photo. Please retake it in good light with your face clearly visible.",
    "selfie_url": "https://cdn.coinzu.app/kyc/a6ac892c-a90f-471f-b05f-953cdb3270d3.jpg"
  }
}
```

`reason_code` values on a rejection:

| `reason_code` | `message` |
|---|---|
| `CZDKYC004` | We could not find a face in that photo. Please retake it in good light with your face clearly visible. |
| `CZDKYC005` | We found more than one face in that photo. Please retake it with only you in the frame. |

### Errors

An automatic rejection is **not** an error — it comes back as `success: true` with `status: "rejected"`. The list below is the real failures.

| Status | `cz_error_code` | `cz_error_message` | Cause | Icon |
|---|---|---|---|---|
| 400 | `CZDKYC002` | Your identity is already verified. | The user is already verified. | `AlreadyVerifiedIcon` |
| 400 | `CZDKYC003` | Your verification is being reviewed. We will update you soon. | An earlier attempt is still waiting on a decision. | `ReviewInProgressIcon` |
| 400 | `CZDSTR001` | Please choose a file to upload. | No file was sent. | `FileRequiredIcon` |
| 400 | `CZDSTR002` | That file type is not supported. Please upload a JPG or PNG. | The file is not a JPEG, PNG or WebP. | `FileTypeInvalidIcon` |
| 400 | `CZDSTR003` | That file is too large. Please upload a smaller image. | The file is larger than 5 MB. | `FileTooLargeIcon` |
| 503 | `CZDKYC007` | Verification is unavailable right now. Please try again shortly. | Face detection could not be reached. Nothing was recorded — the user may simply retry. | `VerificationUnavailableIcon` |
| 500 | `CZDSTR004` | We could not upload that file. Please try again. | The photo could not be stored. | `UploadFailedIcon` |
| 400 | `CZDCOMM001` | Please check the details you entered and try again. | A field failed validation, or an unknown field was sent. | `ValidationFailedIcon` |
| 401 | `CZDAUTH005` | Please sign in to continue. | Authorization header is missing. | `SignInRequiredIcon` |
| 401 | `CZDAUTH003` | Your session has expired. Please sign in again. | Access token has expired. | `SessionExpiredIcon` |
| 401 | `CZDAUTH004` | Your session is no longer valid. Please sign in again. | Access token could not be verified. | `SessionInvalidIcon` |
| 429 | `CZDCOMM005` | Too many requests. Please slow down and try again. | Rate limit exceeded. | `RateLimitedIcon` |
| 500 | `CZDCOMM002` | Something went wrong. Please try again. | Unhandled server error. | `ServerErrorIcon` |

```json
{
  "success": false,
  "cz_error_code": "CZDKYC002",
  "cz_error_message": "Your identity is already verified.",
  "cz_error_description": "User kyc_status is already verified.",
  "cz_error_icon": "AlreadyVerifiedIcon",
  "statusCode": 400,
  "timestamp": "2026-08-27T09:12:44.183Z"
}
```

## Enum values

Every value this endpoint can send or accept for its fixed-value fields.

| Field | Allowed values | Notes |
|---|---|---|
| `status` | `pending`, `verified`, `rejected`, `manual_review` | `pending` is never returned by this route; it exists on the column for rows an admin has not settled. |
| `reason_code` | `CZDKYC004`, `CZDKYC005`, `null` | Non-null only when `status` is `rejected`. |

## Example

```bash
curl -X POST http://localhost:4000/api/kyc/verify \
  -H 'Authorization: Bearer <access_token>' \
  -F 'file=@selfie.jpg'
```

## Notes

- **One endpoint, no follow-up call.** The old `GET /api/kyc/status` and `GET /api/kyc/attempts` were removed. Read the decision off this response; read the standing status later off `kyc_status` on [`GET /api/users/me`](005users.me.md).
- Attempt history is **not** exposed to users at all. Admins see every attempt in the KYC tab (`GET /api/admin/kyc`).
- Branch the screen on `is_final` and `can_retry` rather than on `status` strings, so a new outcome does not need an app release.

- The photo is stored first, then checked. If face detection is unavailable the call fails with `CZDKYC007`, no row is written and `kyc_status` is left untouched, so a retry is always safe.
- The account `kyc_status` is set to the same value as `status` in the same call, and a notification is sent for every outcome.
- Only one attempt may be open at a time: while a row sits in `pending`, a second upload is refused with `CZDKYC003`. A `manual_review` row does not block a retry.
- A borderline photo becomes `manual_review`, never an outright failure — the machine does not turn a real user away.
- Rekognition is called with `DetectFaces` only. No document comparison, no liveness session.
- The full integration guide, including how to run the camera capture, is in `src/modules/kyc/API.md`.
- All dates and times are UTC, ISO-8601 with a `Z` suffix. Send UTC, read UTC, convert only for display.
